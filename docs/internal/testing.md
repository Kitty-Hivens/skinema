# Testing and diagnostics

The test suite outweighs the application code on purpose: skinema is a
high-consequence decoder facing protocol drift, and the bindings layer
has no type system between it and a native crash. Tests are the
maintainability backstop.

## Two kinds of test

- **Pure units, no natives.** The pacer, the pts/rational math, the
  frame mailbox, the clocks, the soname table, the tone-map colour
  maths -- all compile and run with no FFmpeg present. The `Libav`
  facade exists so the upper layers are testable this way.
- **Semantic integration.** Tiny fixture videos generated by the
  `ffmpeg` CLI at test time (never committed binaries), decoded through
  the real bindings, and asserted on *meaning*: frame counts, exact pts
  grids, solid-colour pixels within tolerance, alpha survival -- not
  pixel checksums. swscale is not bit-exact across versions and SIMD
  paths, so a checksum would pin an implementation detail rather than
  test correctness.

Fixtures must use only whitelisted containers and codecs. CI runs the
suite against the trimmed bundle, but a dev box's full system FFmpeg
masks any gap -- a fixture can pass locally and fail every CI platform.
(mpegts, for instance, is not a whitelisted demuxer; a start_time
fixture that used it died CI-wide and moved to matroska.)

## Capability gating

The hard problem this solves: a feature suite that skips on an absent
optional capability reads as **green** even when the bundle is broken.
"Absent" and "present-but-broken" become indistinguishable to CI, and a
false green hid exactly that (Linux libass loaded but exported zero
symbols; the subtitle suites had been skipping all along).

The fix is `SKINEMA_REQUIRE_CAPS` -- a comma-separated list (from
`decode`, `subs`, `webp`) the bundle under test must load:

```kotlin
// Fixtures.kt
fun assumeSubtitleRendering() {
    if (requires("subs")) {
        check(Ass.available) { "SKINEMA_REQUIRE_CAPS lists 'subs' but libass did not load" }
        return
    }
    assumeTrue(Ass.available, "libass not loadable -- skipping subtitle rendering test")
}
```

When a capability is listed, its gate is a loud failure; when it is
not, the suite skips (developer convenience). On top of the per-feature
gates, `CapabilitiesTest` asserts each listed capability loads
**independently of any fixture** -- the antidote to a feature suite
skipping for an unrelated reason (a missing encoder on brew FFmpeg, say)
and never exercising the library at all.

Both `build.yml` and `natives.yml` set the caps per row, so a broken
bundle fails *before it uploads*, in the workflow that built it.
`natives.yml` requires what the tier is supposed to carry -- `core`
`decode,webp`, `decode` adds `subs,formats`, `full` adds `encode` -- so a
tier that quietly lost a capability cannot upload. `build.yml` dogfoods the
`full` tier and holds all of `decode,subs,webp,encode,formats` mandatory on
each of its four rows.

## Test doubles

The runtime is tested without real devices or files through three
doubles in the test sources:

- **FakePcmSink** -- an instant, deterministic audio sink. `write`
  appends to a buffer (no blocking), `framePosition` returns
  bytes-written/4 or a manually set position. It makes A/V sync
  provable: a manually advanced fake DAC releases exactly the frames up
  to its position. It also asserts the stopped-write invariant
  (`writesWhileStopped` must stay 0).
- **BoundedPcmSink** -- the real hardware *shape* with a bounded
  buffer: `write` blocks and parks the writer when the buffer is full,
  and the consumer drives playback manually (`consume(frames)`). It
  keeps audio genuinely mid-stream so loop-wrap parks and
  queue-pinning scenarios cannot self-heal, and a test can assert the
  writer is actually parked.
- **ScriptedFrameSource** -- a synthetic `FrameSource` with no
  files/natives: a grid of frames at a configurable period, a
  `blockAt(index)` latch that stalls the next decode, a
  `maxStartedIndex` watermark, and `decodeCount`/`convertCount`
  probes. It is how the pacer's behaviour under a stalled decode is
  tested deterministically -- the keystone test shows frames present
  from inventory *while* decode is latch-blocked.

Tests assert against meaning and use deterministic, controllable
clocks; wall-clock-rate thresholds cannot survive thrashed shared CI
runners and were reworked out where they appeared.

## Diagnostic commands

`skinema-demo` is the in-repo harness. The commands double as
diagnostics; all take `-Pvideo=<file>` (or `-Pinput`/`-Pout` for the
spike):

| Command                          | Purpose                                                        |
|----------------------------------|----------------------------------------------------------------|
| `:skinema-demo:run`              | play one file in a bare Compose window                         |
| `:skinema-demo:spike`            | headless decode spike -- dump frames, measure decode cost      |
| `:skinema-demo:seekbench`        | scripted seeks, seek-to-frame latency percentiles              |
| `:skinema-demo:soak`             | long looped run, RSS/heap once per minute (memory proof)       |
| `:skinema-demo:harness`          | multi-player grid with optional mount/unmount churn            |

Useful flags and env:

- `-Psound` -- enable audio in the demo.
- `-Psubs=<file>` -- external subtitle file in the demo.
- `-PreadAhead=N` -- read-ahead depth.
- `-Pplayers=N`, `-Pchurn=<seconds>` -- harness fan-out and churn.
- `-Pframes=N` -- limit the spike's frame count.
- `SKINEMA_DEBUG_SEEK=1` -- print sink position at flush/anchor/start
  and the `[pace]` starvation diagnostic; the way seek bugs get
  reproduced headlessly with data.
- `SKINEMA_LIBAV_DIR`, `-Dskinema.libav.dir` -- point at a specific
  native bundle.

A note on CI flakes: `taskset -c 0 ./gradlew test --no-daemon` pins the
build to one core and reproduces runner-starvation flakes locally that
otherwise only appear on thrashed shared runners.

## Where the why lives

When a test encodes a non-obvious rule (the converted-codec ReadOrder
collision, the freeze-first ordering, the phantom-chase probe), the
reasoning is in `../ROADMAP.md`'s milestone entries, not duplicated in
the test. Read the relevant milestone before changing a test that looks
over-built -- it usually guards a bug that was expensive to find.
